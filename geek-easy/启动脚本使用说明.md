# 启动脚本使用说明

## 📋 脚本概览

本项目提供了多个启动脚本，用于不同的使用场景：

### 🚀 主要启动脚本

| 脚本名称 | 用途 | 推荐场景 |
|---------|------|----------|
| `quick_start.sh` | **快速启动** - 一键启动算法动画+监控工具 | ⭐ **日常使用推荐** |
| `start_animation_with_monitor.sh` | 完整启动 - 详细配置和日志 | 调试和详细监控 |
| `start_algorithm_with_jmx.sh` | 仅启动算法动画程序 | 单独运行算法程序 |
| `start_process_monitor.sh` | 仅启动JVM监控工具 | 单独运行监控工具 |
| `stop_all.sh` | 停止所有相关程序 | 清理环境 |

## 🎯 推荐使用方式

### 方式一：快速启动（推荐）

```bash
# 一键启动算法动画程序和JVM监控工具
./quick_start.sh
```

**特点：**
- ✅ 最简单，一条命令搞定
- ✅ 自动处理端口冲突
- ✅ 后台运行，不阻塞终端
- ✅ 提供详细的操作指引

### 方式二：完整启动

```bash
# 完整启动，包含详细配置和日志
./start_animation_with_monitor.sh
```

**特点：**
- ✅ 详细的启动过程显示
- ✅ 完整的JVM参数配置
- ✅ 自动日志记录
- ✅ 优雅的停止处理

### 方式三：分步启动

```bash
# 1. 先启动算法动画程序
./start_algorithm_with_jmx.sh

# 2. 再启动JVM监控工具
./start_process_monitor.sh
```

## 📊 使用步骤详解

### 第一步：启动程序

选择任一启动方式，推荐使用快速启动：

```bash
cd /Users/wangxiaozhe/workspace/geek_leetcode/geek-easy
./quick_start.sh
```

### 第二步：连接监控

1. 启动后会自动打开JVM监控工具界面
2. 在界面中选择 **"手动输入JMX端口..."**
3. 输入端口号：**9999**
4. 点击连接按钮
5. 连接成功后即可看到实时监控数据

### 第三步：查看监控数据

连接成功后，你可以看到：

- 🔌 **端口信息**：显示当前连接的JMX端口
- 💾 **详细堆内存**：Eden区、Survivor区、老年代使用情况
- 🗑️ **GC信息**：垃圾回收算法、Young GC、Old GC统计
- 📈 **实时图表**：内存使用率进度条和百分比
- ⚡ **系统信息**：运行时间、线程数等

## ⚠️ 常见问题

### 1. 端口被占用

**现象：** 提示端口9999已被占用

**解决：** 
```bash
# 停止占用端口的程序
./stop_all.sh

# 或者手动查找并停止
lsof -i :9999
kill <PID>
```

### 2. 编译失败

**现象：** 提示编译失败

**解决：**
```bash
# 手动编译
mvn clean compile

# 检查Java版本
java -version
```

### 3. JMX连接失败

**现象：** 监控工具无法连接到算法程序

**解决：**
1. 确认算法程序已启动：`ps aux | grep AlgorithmTreeLauncher`
2. 确认端口已开启：`lsof -i :9999`
3. 重新启动：`./stop_all.sh && ./quick_start.sh`

### 4. 内存不足

**现象：** 程序启动失败，提示内存不足

**解决：**
- 关闭其他占用内存的程序
- 或修改脚本中的内存参数（-Xmx值）

## 🎯 性能优化建议

### 1. 系统要求

- **内存：** 建议8GB以上
- **Java版本：** Java 8或更高版本
- **操作系统：** macOS/Linux/Windows

### 2. JVM参数说明

**算法程序参数：**
- `-Xms2g -Xmx6g`：堆内存2GB-6GB
- `-XX:ReservedCodeCacheSize=2048m`：代码缓存2GB
- `-XX:+UseG1GC`：使用G1垃圾回收器

**监控工具参数：**
- `-Xms512m -Xmx1g`：堆内存512MB-1GB
- `-XX:+UseG1GC`：使用G1垃圾回收器

2. 检查Java版本和环境变量
3. 确认端口9999未被其他程序占用
4. 尝试重新编译：`mvn clean compile`
